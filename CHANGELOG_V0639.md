# v0.6.39 — Project-Authored Human HTML

## Why
A real FULL delivery showed that “dynamic routes” were still being presented as a capability-driven workflow: a persistent Product/Market/Listing/Strategy/Visual/Asset menu, command cards, numbered strategy/content/evidence items and asset phase rails. The UI was technically dynamic but humanly still read as a pipeline.

## Fix
- Final HTML is treated as a product interface for the current project, not a CBCC capability catalog.
- Persistent capability sidebar is removed.
- Permanent navigation contains only current project identity + return to Project Map.
- First screen becomes a project object map generated from the business objects that actually exist.
- Object labels consume current product / market / platform / locale / asset counts where available.
- Current priority is rendered separately as `当前重点`; next action no longer defines information architecture.
- Generic module subnavigation becomes horizontal contextual lenses rather than a sticky left rail.
- Strategy/content/evidence numbering is visually removed unless the underlying business object genuinely needs sequence.
- Asset Design Card / Visual / Photography-CMF / Copy / Prompt / Production / QA remain lenses on one asset object, not production phases.
- Automatic Operator Execution HTML injection is removed from the primary page flow.
- Automatic `七大工具 / 定价与经济性` capability-proof block injection is removed from the primary page flow.
- v0.6.37 commercial depth remains intact: integrated final render, dynamic asset curation, prompt density, actual-output QA, video authorship, economics/ads/review capabilities.

## Explicitly removed from primary delivery grammar
- fixed left capability menu;
- Product → Market → Listing → Strategy → Content → Visual → Assets → Prompt → Risk → Sources reading order;
- giant operator board injected before the project;
- seven-tool/runtime proof appended as a mandatory human section;
- numbered navigation implying 01→02→03 workflow;
- capability names used as permanent top-level navigation simply because the system supports them;
- same-shell/different-copy HTML and status-first homepage behavior.

## Acceptance
A FULL `index.html` is not acceptable if its permanent navigation mirrors CBCC's capability catalog, if the first screen is a next-step dashboard instead of the project object map, if the operator must follow a universal stage order to reach complete business objects, or if the UI sends the operator to folders/JSON/MD for the actual work.

## Unchanged capabilities
v0.6.37 integrated commercial rendering, Agent visual curation, production prompt density, reference-guided native product generation, production parameter continuity, actual-output QA, dynamic video, advertising/review/economics capabilities remain available.
