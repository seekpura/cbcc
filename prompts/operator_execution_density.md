# Operator Execution Density Authority

## Purpose
The human delivery is not a strategy archive and not a runtime debugger. It is an operating workspace. Every first-class commerce capability must end in objects that an operator can use immediately.

## Default human language
Human delivery is Chinese-first unless the user specifies otherwise. Target-market visible copy remains in its real target language and must be accompanied by concise Chinese meaning/usage so a Chinese-speaking operator can review and execute it without reconstructing the intent.

## Core rule
For every material analysis or recommendation, answer all of:
- **做什么** — exact action;
- **在哪做** — platform/surface/SKU/campaign/asset/field;
- **用什么** — final copy, prompt, script, reference, file or parameter;
- **为什么** — evidence + business logic;
- **什么不要动** — frozen unrelated layers;
- **什么时候做** — priority / sequence when dependency exists;
- **做到什么算完成** — release/QA condition;
- **看什么数决定下一步** — metric / evidence / decision rule.

A result that only diagnoses, scores, validates or says “needs optimization” is not operator-ready.

## Required top-level operating objects
Build only the objects relevant to the project, but when relevant they must be complete.

### 1. Launch Board
For each action:
- priority P0/P1/P2;
- owner role;
- exact action;
- target object ID;
- dependency;
- supplied artifact/link/file when available;
- release state;
- metric / verification;
- next decision.

### 2. Listing Release
For each platform field:
- Chinese field label first;
- platform raw key secondary;
- final target-market copy;
- Chinese meaning/usage companion;
- keyword/search intent mapping;
- Product Truth / Claim trace;
- character/byte/platform check;
- release status.

Do not deliver “copy suggestions” when enough evidence exists to author final copy.

### 3. Asset Production Board
For every image/video asset:
- asset ID + Chinese purpose;
- shopper question / commercial job;
- surface and activation role: LIVE / TEST / ROTATION / SUPPORT;
- product presence decision;
- exact visible copy + Chinese companion;
- model prompt CN;
- model prompt EN / provider-facing language;
- bound source/reference files;
- output spec;
- production route;
- critical camera/light/material parameters only when they change output;
- QA checklist;
- release state;
- local-repair instructions.

The operator must not need to assemble a prompt from five strategy sections.

### 4. Paid Test Queue
For each paid test:
- commercial hypothesis;
- campaign/ad-group/ad/creative IDs where available;
- audience/query/placement scope;
- control;
- variant;
- exact asset request;
- budget/economic boundary;
- primary + guardrail metrics;
- decision rule;
- next action.

### 5. Review Revision Queue
For each customer issue:
- issue/theme;
- exact customer evidence;
- responsibility layer;
- affected listing/asset/product/CX object;
- exact revision;
- frozen layers;
- verification metric;
- READY / NEEDS_PRODUCT_INVESTIGATION / NEEDS_HARD_INPUT.

### 6. Economics Control Panel
Expose only numbers that drive action:
- price;
- contribution;
- contribution margin;
- break-even CPA/CPC/ROAS;
- promo ceiling;
- affiliate/creator room;
- bundle economics;
- current vs allowable acquisition cost;
- missing inputs that materially block a spend/discount decision.

### 7. Release Status
Use business-facing release states:
- `PUBLISH_READY` — can be published after normal platform upload checks;
- `PRODUCTION_READY` — can be generated/shot/edited now;
- `TEST_READY` — can enter a controlled test now;
- `QA_REPAIR` — generated but needs a bounded fix;
- `NEEDS_HARD_INPUT` — impossible to proceed truthfully without a real missing input;
- `HOLD_COMPLIANCE` — specific legal/platform/claim issue;
- `STOP_ECONOMICS` — current action is economically non-viable under supplied inputs.

Do not expose technical statuses such as COPY_RENDER_MODE_REQUIRED as the main operator state when the Agent can resolve the choice internally.

## Unknowns and gates
Normal professional choices are the Agent’s job: layout, product presence, copy-render route, camera grammar, visual carrier, message order, hook type, testing hypothesis and revision scope.

Ask/block only for missing inputs that would force factual invention or materially unsafe execution. Examples:
- unknown product fact required for a claim;
- missing real product reference for an explicitly identity-locked route;
- unresolved legal/platform requirement that controls publication;
- missing unit-economics input required before price/discount/spend commitment;
- provider failure or unavailable production capability.

## Density check
Before release ask:
- Could the operator execute this without another strategy meeting?
- Are final copy/prompt/script objects present, not merely recommendations?
- Are target-language outputs understandable to the Chinese operator?
- Are economics and truth boundaries attached to the action that needs them?
- Is the next measurement decision explicit?
- Can the operator tell which assets are live, tests, rotations and support?

If not, the delivery is not finished even if all runtime contracts passed.
