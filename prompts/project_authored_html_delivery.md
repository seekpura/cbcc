# Project-Authored Human HTML Delivery Authority

The final `index.html` is a human product interface for the current commerce project, not a visualization of CBCC's internal capability catalog and not a workflow diagram.

- First screen = project object map, not a sequence of steps.
- Current priority / next action is separate from information architecture.
- Permanent navigation must not mirror Product / Market / Listing / Strategy / Content / Visual / Assets / Prompt / Risk / Sources.
- No fixed page count and no 01→02→03 implication unless the actual business object is genuinely ordered.
- Asset Design Card, visual execution, Photography/CMF when relevant, visible copy, Model Prompt CN/EN, Production/Assembly Notes and QA are lenses on one asset, not phases.
- Operator execution can be a focus/drawer, not a mandatory giant section before the project.
- Seven-tool/Runtime/hash/Gate proof belongs in secondary Inspector/Archive, not the primary human surface.
- Presentation changes must preserve complete commercial depth and direct inspectability of substantive work.
