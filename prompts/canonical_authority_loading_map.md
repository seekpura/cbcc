# CBCC Canonical Authority Loading Map — v0.6.54

## Purpose
CBCC does not prove capability depth by making one monolithic prompt arbitrarily large. The Host Skill is the routing authority; mature specialist authorities are mandatory inputs when their domain is active. A file existing in `resources/` without being selected/consumed does not count as preserved capability.

## Materialization consumer rule
When `resources/runtime/cbcc/delivery_export.py`, `delivery_workspace.py`, `delivery_html.py` and `commercial_workspace_shell.py` are executable, FULL generation/repair is runtime-first. Host-native materialization is fallback, not permission to invent a replacement shell. Existing-package repairs patch underlying business objects and rerender through the mature consumer, or surgically preserve the existing shell if runtime execution is truly unavailable.

## FULL current-research rule
When platform/market is explicit and a FULL decision depends on current external facts (platform mechanics, submission rules, regulation, religious/holiday calendar, local payment/logistics, market/search/competition/price context), use current public evidence when host tools are available. If reliable current evidence is unavailable, preserve `TO_VERIFY / MISSING_INPUT` and explain which downstream decision remains provisional.

## Selection and consumption rule
- FULL projects activate the complete mandatory set above; task-scoped projects load relevant domains.
- Authority loading is not a checklist visible to the operator. Real business decisions, Design Cards, Prompt values, Human HTML and Measurement/Revision are evidence of consumption.
- Host/Canonical may summarize repeated stable rules, but may not replace specialist production depth with shorter generic prose.
- A specialist authority is preserved only when it changes/constrains downstream outputs.
- Upgrade is additive: newer authority overrides only explicitly conflicting behavior; it never silently deletes mature authority.
