# CBCC Human Workspace Theme Contract v0.6.39

## 定义
`index.html` 是面向项目使用者的完整正式交付，也是一个自包含离线工作区。它不是长篇 Editorial Report、文件浏览器、Markdown 聚合器，也不是固定 SaaS dashboard。

## Project-authored Workspace
**信息架构本身属于设计输出。** 不存在默认主导航、默认页面数、默认首页、默认侧栏、默认卡片网格、默认资产详情阶段或默认“01→02→03”浏览路径。

宿主 Agent 在完成当前项目的语义重构后，根据真实业务对象和人类使用动作决定：
- 哪些对象需要独立界面，哪些应该融合；
- 使用画布、矩阵、组合页、Portfolio、详情 Inspector、对比、搜索、过滤、Drawer、Tabs、时间线、叙事页或其他方式；
- 哪些内容第一屏出现，哪些是次级细节；
- PC / Mobile / fixed-canvas / responsive 的真实目标。

以上表现方式都不是固定模板。禁止把 CBCC 的能力列表、九域、七工具、Runtime 模块、文件目录直接变成导航。

## 内容完整性
动态界面不能以“简洁”为由丢内容。当前项目需要的策略、Listing、视觉/视频、资产生产、Economics/Offer、Ads/Review/Evidence 等人类可读对象应在 HTML 中可直接理解和操作。

同一对象允许把多种信息合并在一个高质量工作面中。例如一个资产 Inspector 可以同时展示购买任务、设计、文案、Prompt、生产和 QA，而不是被迫拆成固定七八个标签。

## 资产体验
资产组合首先是一个被策展的 Portfolio，不是文件列表。每个资产的入口、预览方式、比较方式、变体关系和详情深度由当前资产宇宙决定。

需要完整生产信息时，应在 HTML 内直接展开真实 Design Card / Prompt / Copy / Production / QA；不能只显示 role/status/render-route 后让用户自己去 `assets/<ID>/` 找正文。

## 中文优先
- 默认交付语言 `zh-CN`；用户明确指定时覆盖。
- 目标市场文案保留当地语言原文。
- 外文 Listing / 广告 / 资产文案在同一人类对象提供中文释义或用途。
- 原始字段 key / Asset ID / Provider / hash 等技术信息降级为次级层。

## 视觉系统
视觉主题、密度、动效与交互从当前商品、品牌、CMF、目标市场、平台和工作任务派生。不要给所有项目固定绿色后台、统一圆角卡片、统一左侧栏或相同 Hero 构图。

固定几何目标保持固定几何；只有真实需要多端适配的产品才做 responsive 重构。不要用一个设备方向去预览另一个固定方向的成品。

## 完整内容与源文件
MD / JSON / TXT / per-asset 文件继续作为可编辑、机器、版本和审计真源；用户无需打开这些文件才能理解或执行项目。

## 失败判定
出现以下任一情况即视为交付层回退：
- 固定能力菜单成为一级 IA；
- 每个域都被压成同样的卡片；
- 首页主要是状态徽章/KPI 而不是项目判断；
- 资产详情只给摘要，真正 Design Card/Prompt 藏在目录；
- 为填页面虚构价格、预算或性能数字；
- 视频被压成一个固定时间线模板；
- 页面结构换商品后基本不变，只替换文案和数字。

发生回退时应重做信息架构，不继续给旧模板叠组件。
