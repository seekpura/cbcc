# P1 Domain Depth Batch 2 — Runtime Contracts

## 1. Platform Business Pack Compiler
Platform coverage is two-level:
- **Family planning pack**: defines broad content/operations families for planning only.
- **Exact pack**: `Platform × Site × Program × Category × Surface × Locale`, with current RuleAtoms and source/freshness metadata.

Family planning never establishes submission readiness. Exact readiness requires current scoped evidence for the requested rules and surfaces.

## 2. Listing Compiler 2.0
Semantic strategy remains upstream; deterministic compilation performs:
- classified keyword aggregation and caller-supplied priority;
- platform field contracts;
- char/byte limits when supplied by current rules;
- numeric fact trace;
- source/claim references per field;
- target-language contract propagation.

## 3. Dynamic Asset Architecture
Asset count is an output, not an input. The runtime uses purchase questions, content families and surfaces to produce CREATE/MERGE behavior. Duplicate decision jobs on the same surface merge instead of inflating asset count.

Every asset carries reason-to-exist, incremental information, handoff, surface, production mode, fidelity, source/claim IDs, visible-copy lock and creative brief.

## 4. Asset Compiler
Each approved asset compiles to an independent directory with manifest, strategy, visual contract, photography/layout contracts, CN/EN production prompt, positive-first generation guidance, locked copy, production route and source trace.

Internal workflow state is not serialized into generation prompts.

## 5. Audience / Culture Runtime
The runtime compiles evidence-bounded cultural statements, intersectional dimensions, casting constraints, visual implications and copy implications. Identity dimensions remain context signals rather than automatic behavior predictions.

## 6. Locale / Typography
Target locales compile into script, direction, line-breaking and information-density profiles. This is a production contract, not a claim that copy has received native editorial approval.

## 7. Production Provider Routing
Production mode routes to a provider class such as human photography, composite pipeline, AI image, human/design provider, CG/3D, video or documentation. Routing creates a handoff contract; execution remains a separate authority action.
