# CBCC BUSINESS OBJECT DENSITY MASTER CONTRACT

## 0. 定义

这是 CBCC 的**全业务对象密度合同**。它**不是 Prompt 专项合同**，也不是视觉专项、语言专项或合规专项合同。

它约束 FULL 项目中所有对商业决策有用的人类/机器业务对象：Product Truth、Research、Market / Audience / Culture、Intersectionality、Strategy、Frameworks、Pricing / Economics / Offer、Listing / Search、Content Matrix、Visual Master、Asset Universe、Art Direction、Model Prompt、Video / Creator / LIVE、Advertising Optimization、Review Analysis、RACE、Localization、Compliance / Risk、Measurement / A-B、Evidence / Sources、Operations、Human Workspace。

**中文化不得降密度。任何模块不得摘要替代真实业务对象。任何修复不得把“完整对象”变成“几条结论”。**

所有重大业务对象至少遵守：
`WHAT → WHY → EVIDENCE → TRADEOFF → EXECUTION → MEASUREMENT`。

当某个对象不适用时，写清 N/A 原因；当事实未知时使用 `MISSING_INPUT / TO_VERIFY / ASSUMPTION`，不能用空泛文字补齐。

---

# 1. Product Truth / 产品事实与证据

必须物化：
- 信息完整度；
- source authority / source conflict；
- 核心规格、包装、成分/材质、容量、配件、适用边界；
- **真实卖点 / 可感知利益 / 情绪价值 / 不可宣称项**；
- A/B/C 证据等级；
- claim boundary；
- 事实→卖点→利益→文案/资产的追溯；
- 待确认事实与对 downstream 的影响。

不得把 Product Truth 压成“产品名称 + 三个卖点”。

---

# 2. Research / Market Intelligence

市场研究不是几句“市场有机会”。按项目相关性覆盖：
- **需求 / 搜索 / 竞争 / 价格带 / 评论 / 差评 / 机会 / 风险**；
- 搜索词/长尾词/问题词；
- 竞品结构、集中度、差异化空白；
- 类目惯例与视觉/内容同质化；
- 价格×配置/规格关系；
- 消费者抱怨与未满足任务；
- 平台行为与交易环境；
- 证据来源、时间、置信度；
- 从研究到策略/Listing/资产的具体影响。

无真实数据时标 UNKNOWN/TO_VERIFY，不得编市场规模、热搜量、排名或销量。

---

# 3. Market / Audience / Culture / Intersectionality

必须回答**平台 × 区域 × 人群 × 族裔文化**为什么这样做，而不是只给“目标女性 18–35”。

按相关性覆盖：
- region/subregion/geography；
- age / gender / income-spend / lifecycle；
- language；
- race/ethnicity；
- religion；
- lifestyle / household / usage context；
- platform behavior；
- payment / logistics；
- holiday/calendar；
- stereotype/taboo；
- content/visual/copy consequence。

交叉性至少：**族裔 × 性别 × 年龄 × 收入 × 地域**。每个有意义的 intersection 给：影响、依据/假设、刻板印象防护、执行后果。

不允许用族裔/宗教直接推断肤质、价格敏感、购买意愿或产品需求。

---

# 4. Strategy / Frameworks / Core Commercial Logic

策略必须包含：
- **定位 / 价值主张 / 信息层级 / 传播节奏**；
- target / segment priority；
- purchase barrier；
- belief sequence；
- message hierarchy；
- proof hierarchy；
- differentiation；
- offer role；
- channel/surface role；
- resource tradeoff；
- measurement。

框架关系必须真实参与决策：
- **STP / JTBD / AIDA / FABE / 4P / Funnel**；
- RACE 作为传播流程骨架；
- 框架必须说明“它改变了当前项目哪个决策”，不能只列定义或打勾。

重大策略必须回答 WHY、依据、取舍、执行、指标。

---

# 5. Pricing / Economics / Offer

Pricing / Economics / Offer 不能被视觉任务吞掉。只使用显式输入，缺失数据保持 MISSING_INPUT。

相关时必须覆盖：
- **Price Bands**；
- price valleys / price×configuration；
- unit economics；
- landed cost / platform fee / fulfillment / payment / ads / return assumptions；
- **Contribution** waterfall；
- gross/contribution margin；
- **Break-even** CPA / CPC / ROAS / CVR relationships；
- promo/discount/pack/bundle boundary；
- **Offer Boundary**；
- pricing decision + WHY；
- 对 Listing、Ads、promotion、creator/affiliate 的影响。

禁止把未知成本/费率/CVR 默认成 0 或编造。

按平台相关性物化：
- **关键词 / 标题 / 卖点 / 描述 / 属性 / FAQ / Claim Mapping**；
- search intent / keyword cluster；
- title field logic；
- bullets/key benefits；
- description；
- attributes/specs；
- package contents；
- usage / warning / care；
- FAQ / objection handling；
- claim-evidence mapping；
- locale / exact publishable copy；
- English semantic baseline（非英语市场）；
- 中文释义；
- platform field keys and constraints；
- search→click→understand→trust→objection→action logic。

不能只留一段标题和几句卖点。

# 21. FULL 发布非回退判定

FULL 发布必须同时证明：
1. Product Truth 深度存在；
2. Research / Market / Audience / Culture 深度存在；
3. Strategy / Framework / Pricing 深度存在；
4. Listing / Search / Content Matrix 是可执行对象；
5. Visual Master 与 Asset Art Direction 均存在且不互相替代；
6. Prompt/Production 是商业级高密度；
7. Video/Creator/LIVE 在相关项目中真实物化；
8. Ads / Reviews / Economics 在相关项目中未被省略；
9. RACE / Localization / Compliance / Measurement 是执行对象，不是标题；
10. 中文运营主层没有通过摘要造成降密度；
11. HTML 没有把完整对象隐藏成卡片摘要；
12. 任一新修复没有让另一模块比上一个成熟基线更薄。

**任何模块“有标题、有字段、有一两句话”都不能作为密度 PASS。实际决策、依据、取舍、执行、指标和生产可用性才是证据。**
