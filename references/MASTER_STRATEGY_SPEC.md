# MASTER STRATEGY SPEC — Canonical Full-Chain Requirements

This file is normative. A full STRATEGY run preserves the capabilities in `capability_ledger.yaml`.

## Required sequence
Information audit → focused missing questions → assumptions/decision log → source of truth / Commerce Entity Graph → product/claim audit → research gate → market/platform/region/audience/race-ethnicity insight → STP/JTBD/intersectionality → Decision System → positioning/value proposition → RACE → 4P/conversion funnel → Listing Conversion → Creative System / curation → creative territories / Foundation Anchor → CMF / information design / photography/casting → multi-surface dynamic assets → image/video/creator plan → platform localization → compliance → measurement/A-B → P0/P1/P2 → traceability → package.

## Product fact / claim audit
Separate Real Selling Point / Perceived Benefit / Emotional Value / Pending Claim / Restricted Claim. Evidence A = formal test/certification/reproducible evidence; B = ingredient/material/supply-chain/mechanistic support; C = subjective/pending. Buyer-facing strength matches evidence strength.

## Platform × Region × Audience × Race/Ethnicity
Every material decision explains its fit to platform, market, audience and cultural context. Run intersectionality: ethnicity × gender × age × income × geography × lifestyle. Cultural statements carry evidence/confidence.

## Decision System
Use RACE, STP/JTBD, 4P/funnel and optional AIDA/FABE. Apply Fogg, Means-End, Signaling, FIRST Hero Gate, Cognitive Budget, Commerce Response Ladder and Belief Sequence when they improve a real decision.

## Creative System
Use Product Truth → Research → Curation → Creative Territories → Foundation/Creative Anchor → CMF → Photography/CG → Information Design → Surface Plan → Dynamic Assets → Prompt/Layout Contract → Production → QA → Revision.

## Culture adaptation
Check language, religion, festivals, skin tone, hair texture/style, body type, age, disability, family structure, clothing, body contact, gestures, props, colors, humor and CTA as relevant to the market and asset.

## Photography / CMF
Follow `PHOTOGRAPHY_CMF_SPEC.md`: lens/focal length, camera height/distance/angles, shot size/crop, perspective, product occupancy, negative space, focus/DOF, key/fill/negative fill/rim, modifier type/size/distance, CCT, contrast, exposure/highlight policy, reflection control, shadow behavior, color management, skin-tone handling, material/finish and styling/props.

## Dynamic assets / surfaces
Asset count follows purchase questions, belief sequence, information gain and surface need. Surfaces can include Listing, PDP, Gallery, Longform/A+, Shop, Shoppable Photos, Ads, Video, Creator/UGC, Social, Live, FAQ/CS and Email/CRM.

## Listing
Listing is a conversion system. Include keyword architecture, title, highlights/bullets, description/PDP, attributes/specs, usage, package contents, FAQ/objections and claim mapping. Trace material fields to source/claim/consumer job/asset.

## Feedback and iteration
Reviews, CS, returns/refunds, search and creator feedback map to root cause → responsible module → listing/surface field → asset → revision request. One primary root cause per experiment.

## Final QA
Confirm fact/claim traceability, platform freshness, product fidelity, culture/inclusion, dynamic asset logic, measurement baseline and package completeness. P0 issues block final delivery.
