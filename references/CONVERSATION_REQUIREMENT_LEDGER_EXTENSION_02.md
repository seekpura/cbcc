# CBCC Conversation Requirement Ledger Extension 02 — Explicit Historical Full-System Lock

## Authority
This extension is a **mandatory cumulative requirement authority**. It expands requirements that were previously represented too abstractly by Asset Universe / FULL-depth language and therefore remained vulnerable to host/runtime shortcutting.

It does **not** replace REQ-001..060. It adds REQ-061..090. A future release, cleanup, refactor, HTML redesign, Prompt rewrite or Runtime repair may not summarize these requirements back into one generic sentence such as “support all asset families” or “FULL project”.

The core correction is: **CBCC is a complete commerce operating system, not an asset generator, not a 9-image planner and not a Prompt generator.** Assets are one downstream family inside a larger canonical commerce object graph.

---

## REQ-061 — Canonical commerce object graph is the single business authority
A FULL project must first materialize one canonical business object graph covering, as relevant:
`Project → Sources/Evidence → Information Audit → Product Truth → Research → Market/Audience/Culture → Economics/Offer → Strategy/Frameworks → Listing/Search → Content Matrix → RACE → Cultural Adaptation → Visual Master → Asset Opportunity Universe → Image/Graphic/Scene/Negative/IP/Video/Creator/LIVE → Ads → Review Analysis → Compliance/Risk → Measurement/A-B → Operations → Production/Review/Revision`.

JSON is the canonical machine authority. MD and HTML are projections of the same objects, not separately authored summaries. Prompt and production objects are projections from locked upstream Art Direction/commerce objects.

Acceptance: the same object IDs, decisions, evidence links, target-language copy, Chinese companion text and production values remain traceable across JSON/MD/HTML/Prompt/Package.

## REQ-062 — FULL scope is whole-commerce, not asset-centric
A FULL project may not treat `assets` as the parent object that swallows strategy, Listing, Economics, Ads, Reviews, Culture, RACE, Measurement or Operations. These remain first-class business objects with their own depth contracts and human workspace routes/subviews when relevant.

A project that has rich asset prompts but thin Product Truth/Research/Strategy/Listing/Content/Economics/Ads/Reviews is incomplete.

## REQ-063 — Explicit opportunity-family evaluation; abstract coverage is insufficient
The Agent must explicitly evaluate commercially relevant opportunity families. “Open-world Asset Universe exists” is not enough.

For every family listed in REQ-064..078, record one of:
- `ACTIVATED` + concrete candidates;
- `NOT_NEEDED` + WHY;
- `TO_VERIFY` + missing evidence/constraint;
- `MISSING_INPUT` + exact missing input and downstream effect.

Silent omission is a defect. Platform gallery limits affect only Activation Sets, never this evaluation.

## REQ-064 — Scenario / Lifestyle / Context / Human-use family
Explicitly evaluate scene-led commerce opportunities: real use context, environment, human-use, routine context, scale-in-context, emotional/contextual relevance and locally plausible setting.

A scene is not decorative lifestyle filler. Each activated scene must have a shopper decision job, decisive moment, subject action, environmental logic, props with strategic purpose, culture/inclusion handling and a measurable hypothesis.

## REQ-065 — Negative / Counterexample / Expectation-management family
Explicitly evaluate **阴性图 / 反例图 / 误区纠偏 / 预期管理 / 不适用边界 / 错误使用方式 / 不能代表的结果 / risk clarification** opportunities.

These assets exist to reduce misunderstanding, misuse, unsupported expectation or conversion friction. They must never fabricate failed outcomes, fake before/after results, medical deterioration or unsupported comparative proof.

Each activated negative/counterexample object must state:
- misconception / expectation being corrected;
- truth/evidence boundary;
- what is shown versus explicitly not claimed;
- visual carrier;
- copy strength;
- risk/compliance review;
- next shopper action.

## REQ-066 — Brand IP / Distinctive Memory / Brand World family
Explicitly evaluate brand-memory opportunities beyond transactional SKU selling:
- distinctive brand assets;
- recurring visual mnemonic;
- campaign language;
- brand world / scene world;
- IP character/mascot only when strategically justified;
- signature graphic/material/motion motif;
- long-term recall asset;
- campaign/seasonal brand expression.

Do not force a cartoon mascot. The requirement is to assess whether the project needs a durable brand-memory layer and, if activated, materialize it as a real object with continuity rules and deployment logic.

## REQ-067 — Packaging Trust / Unboxing / Contents / Size / Compatibility family
Explicitly evaluate packaging and transaction-trust opportunities:
- package front/back/side/label trust;
- what-you-receive / contents;
- unboxing;
- applicator/accessory detail;
- size/scale demonstration;
- compatibility/fit where relevant;
- package condition/storage/handling instructions where relevant.

These must use real package/source truth and must not invent accessories, dimensions or pack claims.

## REQ-068 — Ingredient / Formula / Material / Texture / Detail / Macro / Proof family
Explicitly evaluate evidence and sensory-detail opportunities:
- ingredient/formula information;
- material/finish study;
- authentic texture/macro only when source truth supports it;
- detail photography;
- mechanism/evidence information design;
- source-document evidence view;
- proof hierarchy.

Do not substitute molecular-ball/lab clichés for evidence. Do not invent product texture, efficacy result, certification or clinical proof.

## REQ-069 — How-to / Routine / Usage / FAQ / Objection / Comparison family
Explicitly evaluate:
- how-to steps;
- routine integration;
- usage/warning/care;
- FAQ;
- objection handling;
- expectation clarification;
- comparison only when truthful and evidence-backed.

Each object must connect to a real shopper barrier and hand off to the next decision.

## REQ-070 — A+ / PDP / Longform / Specification / Source-document family
Explicitly evaluate long-form commerce surfaces separately from gallery images:
- PDP detail modules;
- A+/rich content;
- long-form explanation;
- specifications;
- source/document views;
- comparison tables;
- trust/FAQ modules.

Longform may reuse evidence but must adapt hierarchy, depth and interaction to the surface rather than resize gallery creative.

## REQ-071 — Paid Media / Performance Creative family
Advertising is not “extra image variants”. Explicitly evaluate Paid/Spark/performance creative across hooks, audience states, proof routes, offers, CTAs, landing continuity and economics.

Every activated paid variant records:
`audience state → tension → creative hypothesis → changed variable → proof → offer → CTA → landing → metric/guardrail → spend/economics boundary → next decision`.

## REQ-072 — Social / Seeding / Organic Content family
Explicitly evaluate organic/social/seeding content that is not simply a resized PDP image. Define platform-native hook, conversational or editorial carrier, social proof behavior, caption/copy, interaction goal, cultural fit and measurement.

## REQ-073 — Creator / UGC / Affiliate family
Explicitly evaluate creator/UGC/affiliate opportunities. Activated objects must define:
- creator role/persona relevance;
- performance mode (POV, direct-to-camera, observed demo, instructional, etc.);
- real product handling;
- script/VO/dialogue;
- disclosure/claim boundary where relevant;
- local language naturalness;
- offer/CTA/affiliate handoff;
- measurement/test delta.

Do not fabricate personal experience, professional authority or usage history.

## REQ-074 — Product Video / Short Video / PDP Video family
Video is a first-class time-based commercial object, not static-image motionization.

Explicitly evaluate and, when activated, author:
`shopper tension → narrative carrier → first frame / first 1–3 seconds → shot sequence → beat timing → product presence timing → subject motion → camera motion → visible copy/subtitle → VO/dialogue → audio/SFX/music-rights → transition → CTA hold → cover → landing/attribution → QA → repair`.

Narrative shape is dynamic; no fixed five-beat template.

## REQ-075 — LIVE commerce family
Explicitly evaluate LIVE when commercially relevant. Activated LIVE objects define:
- host/creator role;
- opening/retention mechanism;
- demonstration/education loop;
- objection handling;
- product/offer sequence;
- comment/Q&A handling;
- claim/compliance boundaries;
- CTA/checkout handoff;
- repetition cadence;
- measurement and learning.

## REQ-076 — Store / Banner / Landing / Campaign / Seasonal family
Explicitly evaluate store-level and campaign surfaces separately from listing gallery:
- store banner;
- landing hero;
- campaign page;
- seasonal/holiday modules;
- launch/event creative.

They may use a wider brand-world grammar and must still preserve truth, localization, cultural/religious context, CTA and responsive/surface behavior.

## REQ-077 — CRM / Lifecycle / Post-purchase / Retention family
Explicitly evaluate lifecycle content where relevant:
- welcome/onboarding;
- usage education;
- post-purchase instructions;
- replenishment/reminder;
- cross-sell/bundle only when evidence/offer supports it;
- review request;
- service/FAQ recovery.

Lifecycle content is part of commercial continuity, not automatically out of scope.

## REQ-078 — Test Pool / Rotation Pool / A-B / Multivariate family
Explicitly materialize test/rotation opportunities when uncertainty is commercially meaningful. Variants must state changed variable, held constants, hypothesis, metric/guardrail, deployment pool and next-decision rule.

Do not count decorative variants as tests. Do not merge valid variants because they share a shopper question.

## REQ-079 — Surface-native specialization and Activation boundary
Every relevant surface must have its own execution logic: gallery, search thumbnail, PDP longform, paid ad, creator feed, short video, LIVE, banner, landing, CRM, etc.

Platform capacity only constrains the simultaneous Activation Set. The complete opportunity universe and production portfolio remain larger when justified.

## REQ-080 — Project-level Visual Master and portfolio rhythm remain separate from per-asset design
A project must have a Visual Master / brand-world system before or alongside per-object Art Direction. It covers continuity tokens, palette/HEX, typography role, material/light world, scene logic, information density, cultural representation, camera language where relevant, motion logic and anti-template rhythm.

Per-asset Art Direction may intentionally break the dominant rhythm when its job requires it. Repetition needs a commercial reason.

## REQ-081 — Per-object Art Direction applies beyond still images
Structured Art Direction is required for any production object that changes a human-visible/audible experience: image, graphic, scene, negative/counterexample, IP/brand-memory, video, creator, LIVE cover, paid creative, banner, landing module, etc.

The fields are route-specific but must cover relevant commercial job, subject/action/scene, product role, composition, evidence, copy/type, culture/inclusion, CMF/material, camera/light, motion/audio/timing, output and repair ownership.

## REQ-082 — Commercial-grade Prompt density and concrete parameter consumption
Model Prompt CN/EN are lossless generation-plane projections of locked Art Direction, not short summaries.

For each activated provider-generated object, consume every selected pixel/frame/audio-changing decision relevant to its route. A READY prompt may not collapse scene, action, geometry, typography, culture, material, light or motion into generic adjectives.

Prompt length alone is not the metric. `missing_decisions=0` or equivalent concrete-value continuity is required.

## REQ-083 — Dynamic/temporal prompt continuity
For video/creator/motion objects, Prompt/Production must preserve timing, beat, subject motion, camera motion, text timing, VO/subtitle/audio roles, transitions, product identity continuity and first-frame/cover logic. A static prompt plus “animate this” is insufficient.

## REQ-084 — Product Presence, Product Fidelity and real-reference route remain independent
Presence is a commerce/creative decision; fidelity is a truth/production constraint.

Real source availability must not force product-everywhere. When a real product is visible, `REFERENCE_GUIDED_NATIVE_LOCK` is the default integrated route unless explicit exact-pixel intent requires `EXACT_PIXEL_COMPOSITE`.

## REQ-085 — Human/culture/inclusion execution is concrete, not a principle label
When people appear, author casting role, age/context, skin tone, hair texture/style, grooming/makeup, wardrobe/accessories, body/age/disability representation, religious/cultural presentation, pose, expression, gaze, hands, product interaction, stereotype guard, AI-bias review and relevant exposure/lighting handling.

## REQ-086 — Photography / lighting / CMF parameter closure is scene-derived
For photographic routes, selected focal length, working distance, camera geometry, focus/DOF, exposure, shutter/ISO when relevant, key/fill/negative/rim, modifier geometry, CCT/WB, ratio, highlight/shadow policy, reflection/polarization, Prelight, skin handling, material response, color management and finishing must derive from the authored scene/subject/material and survive to the acting production plane.

No repeated camera preset across unrelated objects without a scene-specific reason.

## REQ-087 — Listing / Economics / Ads / Reviews / Research cannot be collapsed into asset metadata
These business capabilities remain deep canonical objects even when the project’s visible output includes many assets. They require their own evidence, decisions, tradeoffs, execution and metrics. An asset’s `strategy` field does not substitute for them.

## REQ-088 — Source/Evidence/Assumption/Decision lineage is first-class
Every major fact and decision preserves:
`source → authority/type → recency → exact fact → interpretation → confidence → assumption boundary → downstream use → conflict → decision/tradeoff → proof object`.

Research existence alone is not enough; downstream consumption must be inspectable.

## REQ-089 — Human Workspace must expose full canonical objects without density loss
`index.html` is a complete routed human workspace. It must not become a card-wall or summary dashboard. It must expose full Product Truth, Research, Market/Audience/Culture, Economics/Offer, Strategy, Listing/Search, Content, RACE, Visual Master, opportunity families, per-object Art Direction, Prompt CN/EN, Visible Copy, Production Notes, Ads, Reviews, Evidence/Risk, Measurement and Operations as relevant.

JSON/MD may remain editable/source layers; users must not need them to recover missing core content.

## REQ-090 — FULL package lineage + actual-output boundary
FULL package must preserve canonical machine truth, human projections, editable/source material, production packages, Source Ledger, object manifest, materialization audit and delivery manifest.

Provider output is not implied by planning. Only real Provider Result → Review → Local Revision → lineage/hash can satisfy actual-output QA. Until then status remains `E2E_PENDING` for those layers.

- JSON is canonical machine truth;

A parity audit must compare object IDs and canonical decision hashes/field-value signatures rather than only file existence or headings.
