# CBCC MASTER CONSTRUCTION CONTRACT

## 0. 这是什么

这是 Cross-Border Commerce Creative 的**施工总纲 / 唯一不可回退母合同**。它不是单一 Prompt、不是某个页面模板、不是验证器说明，也不是某次 KIYUU 项目的特例。

它约束的是整个系统从 Product Truth → Research → Strategy → Pricing/Economics/Offer → Listing/Search → Culture/RACE → Visual/Photography/CMF → Asset Universe → Image/Video/Creator/Ads → Prompt/Production → Review/Learning → Human HTML 的完整能力连续性。

**升级只能做加法。修复一个维度不得压缩另一个维度。**

以下行为一律视为回归：
- 为了中文化，把策略、市场、人群、视觉、摄影、资产或 Prompt 内容压成摘要；
- 为了合规，把商业创意变成规则检查器；
- 为了 Prompt 纯英文，把已选摄影/构图/灯光/CMF/动态参数删掉；
- 为了 UI 简洁，把九域、Listing、Pricing、Visual、Asset、Ads、Review 等真实业务对象缩成几张卡片；
- 为了固定平台图数，把 Asset Universe 剪成 7/9 张；
- 为了产品真实性，强制所有资产都出现产品或全部走 exact-pixel composite；
- 为了验证方便，按字段名/标题存在就判 PASS；
- 为了压缩篇幅，把商业级高密度生产对象改写成几句泛化描述。

# 1. 产品事实、证据与强监管硬合同

## 1.1 先做 Product Truth
任何 FULL 项目先完成事实审计，再做策略。必须区分：
- 真实卖点；
- 可感知利益；
- 情绪价值；
- 不可宣称项 / Claim Boundary。

证据等级固定定义：
- **A=检测报告/官方认证/可复现实测**；
- **B=供应链或成分机理支持**，也包括可核验规格、定量配方、明确供应链文件等有边界支持；
- **C=主观体验/待验证**，包括感官体验、创意假设、尚未有实证的用户感受。

**C 级不得作硬宣称。**

## 1.2 合规与宣称证据为 P0
功效、成分/浓度、认证/通知、价格、销量/排名、医疗/美妆/食品/金融等强监管品类必须单列证据检查。不得编造。

缺失外部事实使用：`MISSING_INPUT / TO_VERIFY / ASSUMPTION`。缺失某项外部 readiness 只阻断该项，不得因此停止其他策略、创意、Listing、资产生产。

# 2. 策略硬合同

## 2.1 所有重大策略必须回答 WHY
每条重大策略至少给出：
`WHAT → WHY → EVIDENCE → TRADEOFF → CONSUMER LOGIC → PLATFORM LOGIC → REGION/CULTURE LOGIC → BUSINESS LOGIC → EXECUTION → MEASUREMENT`。

必须回答：为什么这个平台、这个区域、这个人群、这个族裔文化背景下要这样做。

禁止只给“年轻、优质、高端、转化、现代、清爽、premium”等空泛形容词。

## 2.2 依据 + 取舍
策略每条给**依据 + 取舍**，表格优先。没有取舍的“全都要”不是策略。

预算/周期不足时：
- **P0=不做会翻车**；
- **P1=影响效果**；
- **P2=加分项**。

必须写明保什么、砍什么、为什么、依赖条件、何时恢复。

# 3. 文化、交叉性与 RACE 传播流程

## 3.1 平台 × 区域 × 人群 × 族裔文化
FULL 必须显式处理：
`platform / market_region / subregion_geography / audience_segments / age / gender / income_spend / language / race_ethnicity / religion / holiday_calendar / payment / logistics / local_regulation / platform_behavior / search_demand / competition / price_band / intersectionality / stereotype_taboo`。

### 交叉性
至少分析：**族裔 × 性别 × 年龄 × 收入 × 地域**，必要时加语言、宗教、生活方式。

每个有意义的交叉组合给：
- 影响；
- 依据或假设；
- 刻板印象防护；
- 可执行后果。

不得把族裔/宗教直接推断为肤质、价格敏感、购买意愿或产品需求。

## 3.2 族裔文化适配
单列**族裔文化适配检查表**，分析：
- 族裔身份；
- 语言；
- 宗教；
- 节日；
- 禁忌；
- 肤色/发型/体型/家庭结构呈现；
- 包容性表征；
- 刻板印象规避。

平台内容矩阵逐条校验：脚本、模特、服化道、配色、CTA。

## 3.3 RACE
**RACE = Research → Action → Communication → Evaluation**。

- Research：市场/平台/人群/族裔文化/竞品/产品事实研究；
- Action：定位、信息层级、内容矩阵、拍摄执行、预算节奏；
- Communication：分平台传播、达人/UGC/广告/私域、语言本地化；
- Evaluation：指标、归因、A/B 测试、复盘迭代。

框架关系：
- RACE 做流程骨架；
- STP + JTBD 定策略；
- AIDA / FABE 定内容结构；
- 4P / 内容漏斗定转化。

不得机械套模板，必须解释每个框架在当前项目具体改变了什么。

FULL 必须输出：
- **RACE传播框架执行表**；
- **族裔文化适配检查表**；
- 分平台内容矩阵中增加 `RACE阶段` 与 `族裔文化适配/禁忌校验`。

# 4. 平台执行与本地化硬合同

## 4.1 平台执行考虑
按实际 Surface 处理：
**尺寸、时长、封面、字幕、音乐版权、流量机制、CTA、落地页、UTM 与归因**。

还应包含平台/人群/选题/钩子/脚本结构/视觉形式/指标/RACE/文化校验等。当前规则、算法、活动机制不确定时标**待查证**，不得凭记忆编造。

## 4.2 区域本地化考虑
必须处理：
**语言回译、节日日历、支付物流、宗教禁忌、当地法规**。

不确定标**待查证**，并说明哪项 downstream 决策因此仍为 provisional。

# 5. 视觉、摄影、CMF 与包容性执行

## 5.1 视觉总策略必须可执行
至少给到：
- 风格关键词；
- 情绪板方向；
- 构图规则；
- 主/辅/背景/文字色 HEX 及对比逻辑；
- 灯光方向、色温、光比、柔硬；
- 镜头焦段；
- 景别；
- 机位；
- 场景；
- 道具；
- 模特与服化道；
- 平台尺寸；
- 镜头表 / Shot List。

## 5.2 视觉包容性摄影为 P0
当人、手、身体出现时，必须考虑：
- 深肤色曝光；
- 深肤色暗部保护；
- neutral bounce / reflector / diffusion；
- 发质造型；
- 体型；
- 残障；
- 年龄呈现；
- AI 生成偏见复核。

如给具体曝光补偿，必须写明它只是 **Prelight 起始值**，最终按真实主体、灯光、波形/直方图、肤色纹理校验，不得把肤色变成固定曝光公式。

## 5.3 摄影式路线的 Production Parameter Closure
对相关资产，逐资产闭环：
- 构图；
- 相对位置；
- 尺度；
- 产品占画；
- 焦点路径；
- 负空间；
- 焦段；
- 工作距离；
- 机位高度 / yaw / pitch / roll；
- 景别；
- 对焦面 / 景深 / 光圈；
- 相关时快门 / ISO；
- key / fill / negative / rim；
- modifier 尺寸、距离、角度；
- CCT / WB；
- 光比；
- 阴影 / 高光政策；
- 反射 / 偏振；
- Prelight；
- CMF / 材质；
- 色彩管理；
- finishing。

如果 Agent 已经选定一个会改变像素/运动/时间轴的参数，下游 Prompt/Production 必须真实消费它，不能只保留字段名。

# 6. 商业创意与 Asset Universe

## 6.1 七大一等能力
七大一等能力始终保留：
1. Market Research；
2. Product Strategy，含 **Pricing / Economics / Offer**；
3. Listing Creative；
4. Product Image；
5. Product Video；
6. **Advertising Optimization**；
7. **Review Analysis**。

视觉任务不能挤掉商业能力，中文化不能挤掉视觉/Prompt 密度，合规不能把 Agent 变成 Gate。

## 6.2 Dynamic Asset Universe
**Asset Universe 不受平台槽位总数限制**。平台 7/9 图只限制同时激活集合，不限制总资产、测试池、轮换池、广告、详情、A+、Social、Creator、Video 等。

资产数量由购买决策问题、Surface、创意假设、测试与运营需求决定。允许同一决策/Surface 多个明确 Variant，只要商业假设/视觉机制不同。

## 6.3 产品是否出现
**产品是否出现由逐资产策展决定**。Product Presence 与 Product Fidelity 独立。

真实商品需要出现时，默认使用 **REFERENCE_GUIDED_NATIVE_LOCK**：真实参考图作为强 Reference Input，完整成图中原生生成并保持包装几何、比例、结构、Logo、品牌文字、标签版式、主色、材质身份。

只有用户明确要求源图像素层一丝不动时才使用 **EXACT_PIXEL_COMPOSITE**。

不得全局强制：产品必须出现 / 产品不能出现 / 必须无文字 / 必须后期排字。

## 6.4 逐资产 Art Direction
每个生产资产必须有**逐资产 Art Direction**，至少包括：
- 消费者问题；
- 购买障碍；
- 目标信念；
- Strategic Job；
- 增量信息；
- Visual Carrier；
- Product Presence / role；
- decisive moment；
- subject / action / environment / props；
- composition grammar / spatial rhythm / scale / depth / focal path / negative space；
- evidence hierarchy；
- copy density / typography role；
- camera / focus / exposure（相关时）；
- light geometry / CMF / material / color；
- human/casting（相关时）；
- surface/output；
- editable/frozen layers；
- business hypothesis / success metric；
- 与相邻资产的 rhythm delta。

不能把完整 Design Card 压成 `carrier / occupancy / camera / lighting` 几个摘要字段。

# 7. Model Prompt 与生产对象密度合同

## 7.1 四对象必须分离
每个生产资产必须分离：
1. **Model Prompt CN**；
2. **Model Prompt EN**；
3. **Visible Copy Block**；
4. **Production / Assembly Notes**。

不得把它们合并成一个短 Prompt 或一个 JSON 摘要。

## 7.2 商业级高密度
Model Prompt 必须是**商业级高密度**、model-native、可直接生产的完整指令，不是 3～6 句概括，也不是字段拼接。

**不得压缩为摘要式 Prompt。**

Prompt 应把当前资产真正选定且会改变结果的内容自然写入：
- surface / output；
- commerce objective；
- creative thesis；
- visual carrier；
- product role / reference behavior；
- scene / decisive moment；
- composition geometry；
- visible copy / typography（当路由需要）；
- evidence representation；
- camera / optical grammar；
- lighting program；
- CMF / material realism；
- color world / grade；
- human/culture execution（相关时）；
- finishing；
- truth/exclusion boundary。

Prompt 压缩只能删除重复措辞，不能删除任何已经选择、会改变像素/动作/时间轴/排版/材质响应的具体值。

## 7.3 Prompt 语言
- Model Prompt CN：中文 canonical 执行语义，可包含准确目标市场原文；
- Model Prompt EN：英文 provider-readable 执行说明，不能混入中文执行句；
- 非英语目标市场可见文案：目标市场原文 + English semantic baseline + 中文释义；
- 英语目标市场：English exact copy + 中文释义。

英语层存在不代表最终图片必须显示英文。

## 7.4 Production / Assembly Notes
必须覆盖相关的：
- source/reference role；
- fidelity；
- copy-render mode；
- editable/frozen layers；
- provider route；
- assembly order；
- QA；
- smallest responsible repair；
- local revision boundary。

# 8. Video / Creator / LIVE / Ads / Reviews

## 8.1 Video / Creator / LIVE
**Video / Creator / LIVE** 是一等生产面，不是 PDP 静态图 resize。

叙事结构由购买决策动态推导，不固定五段式。对相关项目处理：时长、beat、shot sequence、subject motion、camera motion、frame rate/stabilization、字幕、VO、CTA hold、音乐/版权、平台原生节奏、归因。

## 8.2 Ads
Advertising Optimization 必须连接：商业假设、受众状态、创意机制、offer、landing、经济模型、归因与测试，而不是只给广告文案。

## 8.3 Reviews
Review Analysis 必须进入：真实评论结构、问题分类、购买障碍、退货/差评原因、Listing/产品/创意的责任层、最小修复、学习闭环。

# 9. 中文、人类交付与目标市场语言

## 9.1 中文是运营 canonical，不是内容缩水理由
项目、Product Truth、市场、人群、交叉性、策略、框架、Visual、摄影、资产详情、RACE、文化、本地化、合规、证据、Economics、执行与测试等运营业务对象，以中文作为主层。

技术名词、原始平台 key、专有名词、INCI、相机/灯光参数可以保持原样嵌入中文句子。

**中文化必须保留原商业深度与参数密度，一字不应因为翻译目标而自动摘要。**

## 9.2 外文同对象释义
目标市场原文、EN Prompt、外文来源/评论等必须在同对象或直接 subview 提供中文翻译/用途说明；不能藏到远程附录。

# 10. HTML / Workspace / 媒体交付

## 10.1 cbcc-commercial-v1
保留 **cbcc-commercial-v1** 成熟 routed SaaS 交互底座：
- 一次一个一级工作面；
- 项目作者化业务对象；
- module subview / lens；
- 独立 `asset/<id>` 详情；
- search / copy / back / hash route；
- responsive navigation；
- print / PDF projection。

九域是完整度合同，不是固定 9 页；禁止把 FULL 全部摊成一张长流水页，也禁止换成固定 dashboard/card grid。

## 10.2 自包含 HTML
最终人类 `index.html` 必须是**自包含 HTML** 或至少对所有展示媒体具备 inline data/blob/fallback。不能因为单独打开 HTML 就丢产品图。

源媒体继续放 `sources/` 用于可编辑性与 provenance；Human Preview 不能只依赖相对路径。

# 11. 执行锁

执行顺序：
**信息审计 → 待确认清单 → 明确假设 → 再输出**。

信息不足最多列 10 个关键问题，随后在明确假设下继续，不得停工。

单独写**假设与决策日志**：
- 哪些是事实；
- 哪些是假设；
- 做了什么决定；
- 为什么这样取舍；
- 对执行有什么影响；
- 用什么指标/证据验证。

平台规则、算法、法规不确定标“待查证”，禁止编造。

# 12. FULL 人类输出结构合同

FULL 至少完整覆盖以下九域，实际 UI 结构由项目作者化：

1. 信息完整度、待确认清单、假设与决策日志；
2. 产品真实事实审计与卖点分级表（真实卖点/可感知利益/情绪价值/不可宣称项/证据等级）；
3. 平台×区域×人群×族裔文化洞察（含交叉性、文化适配点、禁忌与刻板印象规避）；
4. 营销框架与核心策略（定位、价值主张、信息层级、传播节奏、4P/内容漏斗）；
5. **视觉总策略与拍摄执行清单**（风格、构图、配色HEX、灯光摄影框架、焦段、景别、机位、场景、道具、模特服化道、平台尺寸、镜头表）；
6. **分平台内容矩阵表**：平台/人群/选题/钩子/脚本结构/视觉形式/CTA/指标/RACE阶段/族裔文化适配与禁忌校验；
7. RACE传播框架执行表：阶段/目标/关键动作/输出物/平台/文化校验/指标；
8. 族裔文化适配检查表：文化适配点/包容性表征/刻板印象与禁忌/校验结果/修改动作；
9. 合规、文化敏感与风险清单；评估指标与A/B测试建议；P0/P1/P2执行优先级与下一步需补充信息。

这些不是标题存在检查，而是必须包含真实决策和可执行深度。

# 13. 发布前自检与非回退矩阵

输出前自检：
- 是否编造？
- 是否回答“为什么”？
- 是否做族裔文化校验？
- 是否过合规？
- 是否给指标？
- 假设是否标注？
- 中文是否只是翻译而没有压缩原内容？
- 视觉/摄影是否执行到参数层？
- Prompt 是否仍是商业级高密度？
- Asset Universe 是否被平台槽位误裁？
- 是否过度重复同布局/同载体/同产品占画？
- Video/Creator/Ads/Review 是否在相关项目中真实物化？
- HTML 媒体是否可独立打开？

发布回归必须验证跨维度不丢能力，详见 `references/RELEASE_NON_REGRESSION_MATRIX.yaml`。

# 14. 最终原则

1. **升级只能做加法。**
2. **修复一个维度不得压缩另一个维度。**
3. 中文、合规、UI、Prompt 纯度、媒体可移植性都只是质量维度，不能成为削薄商业内容的理由。
4. Agent 负责闭合商业与创意决策，不把正常专业选择转成用户门禁。
5. 验证器用于发现真实回归，不是产品本身，也不能靠字段/标题/布尔值制造 PASS。
6. 最终交付质量以真实人类 HTML、真实业务对象、真实逐资产生产对象以及实际生成/Review 结果为证据。
