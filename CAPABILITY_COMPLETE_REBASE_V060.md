# CBCC v0.6.0 Capability-Complete Rebase

## Current product definition
CBCC is not a Gate system and not a prompt checker. It is a professional cross-border ecommerce strategy-to-production system whose primary output is an executable commercial plan and a production-ready asset language.

## Current authoritative chain
`Product Truth / Evidence → Market / Competitor / Shopper → SKU / Offer / Economics → Positioning / Value Proposition → Message Architecture → Listing / Search / Platform Content → PLAN + RACE → Product Visual Intelligence → Creative Opportunity Universe (6–12 mechanisms) → Direction Synthesis / Council → Direction Lock / Creative Anchors → Dynamic Surface & Information Assetization → per-asset Visual Expression → Photography/CMF/Layout → Design Card → CN/EN Canonical Prompt → Provider / Revision → Measurement / Learning`

## Capability closure addressed in v0.6.0
1. **RACE semantics** are correct and operationalized per asset.
2. **Creative search** exists even when no user direction is supplied: compile 6–12 product/decision/PVI/Surface-derived opportunity mechanisms first, then synthesize 3–5 directions; selection is no longer a passive scorer or a fixed style-menu choice.
3. **Product Visual Intelligence** gives downstream visual work a product-specific visual truth source.
4. **Foundation / Creative Anchor** responsibilities are separated.
5. **Surface architecture** is dynamic and no longer assumes every content node should become an image.
6. **Product Presence** is a decision, not a universal rule.
7. **Asset differentiation** is encoded through decision-specific expression variants and spatial rhythms.
8. **Design Card** carries complete commercial + creative + production reasoning at asset granularity.
9. **Canonical prompts** are full production documents in both Chinese and English rather than compressed summaries.
10. **Provider Jobs** consume the deep prompt/renderer/QA contract.
11. **Paid Campaigns** are independent campaign systems; Creator/Video/Live have native execution logic.
12. Existing market, economics, listing, platform, culture, evidence, production, revision and learning systems remain part of one mainline.

## Reference-project migration principle
The rebase borrows mechanisms proven useful in mature reference projects—Product-Truth-led visual runtime, dynamic Surface architecture, Content/Decision object lineage, Foundation/Anchor separation, per-asset design contracts, canonical prompt production, deterministic tool boundaries and precise revision invalidation. It does **not** copy fixed nine-image templates, Brazil/Amazon-specific assumptions, or duplicate a second visual runtime beside CBCC.

## User acceptance boundary
The user owns real execution acceptance. This codebase should not declare a capability “unfinished” simply because a live external renderer has not yet been exercised by the assistant. Future engineering should be driven by concrete output failures or requested capability gaps and should repair the smallest implicated runtime layer.
